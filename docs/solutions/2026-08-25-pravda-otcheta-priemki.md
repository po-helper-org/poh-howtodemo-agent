# Отчёт приёмки врал трижды: тесты «в каталоге без клона», источник «Issue #1», причина без деталей

## Ситуация

Все четыре правки продиктованы живым прогоном на живой задаче — ни одну не поймали 97 тестов
до него.

1. CLI-шаг «Запустить тесты в `tests/`» отработал в каталоге без клона репозитория:
   `npm error enoent Could not read package.json`, код возврата 254. Отчёт объявил «тесты
   продукта не проходят» и выдал `demo:failed`. Продукт был ни при чём.
2. В отчёте стояло «Источник требования: Issue #1, шаг 5» — на задаче #100: модель списала
   номер из примера промпта.
3. «Шаг не запускался: окружения не было» — и всё. «PR не найден» и «в контракте окружения
   нет команды старта» лечатся по-разному, и молчать о разнице — отправлять человека гадать.

## Причина

Шаг исполнялся без того, что ему нужно для исполнения; поля, попадающие в вердикт, писала
модель; у отсутствия стенда была одна формулировка на все причины.

## Решение

- Рабочая копия приезжает вместе со стендом: `Stand` несёт `workdir`, и без него CLI-шаг
  помечается `blocked` — ровно как HTTP без стенда. Правило общее: шаг не исполняется без
  того, что ему нужно; исполнить и отчитаться о провале хуже, чем честно сказать «не запускался».
- Поле `source` перезаписывается кодом (`plan.build(..., issue=)`): ссылка на источник —
  часть вердикта, а вердикт модель не пишет нигде.
- `RunReport.stand_detail` доносит причину из `Stand.detail` — «PR не найден» и «нет команды
  старта в контракте» видны в отчёте по-разному.
- Подготовка к боевой валидации (этапы 0–1): сеть стенда выясняется у самого докера
  (`docker inspect` хоста), потому что переменных `HOWTODEMO_*` внутри воркера нет — compose
  контура их не пробрасывает, и пустая сеть означала бы контейнер в дефолтной сети,
  недостижимый по имени; неудачный inspect деградирует в «без --network».
- `scripts/live.py` — цикл отладки секунды вместо получаса: тот же `run.verify`, настоящий
  GitHub по токену `gh`, настоящий докер, настоящая модель; не участвуют только Temporal
  и воркер контура. Наружу по умолчанию не пишет ничего (ни комментария, ни меток, ни ветки
  с уликами) — публикация только явным `--push`; `--plan FILE` подставляет готовый план
  и не зовёт модель. Уже окупился: подтвердил за секунды все правки среза.
- Промпт трансляции переехал в пакет: он часть договора с моделью наравне с форматом плана,
  копия в репозитории-потребителе рано или поздно отстаёт.

101–108 тестов, pyflakes чист.

## Как проверить

Прогон живого цикла на задаче без клона: CLI-шаг `blocked`, вердикт `demo:partial` вместо
`demo:failed`; «Источник требования» — номер самой задачи. `pytest -q`.

## Уроки

Исполнить шаг в неподходящем окружении и отчитаться о провале продукта — хуже, чем `blocked`.
Всё, что попадает в отчёт как факт (номер источника, номер шага), пишет код, а не модель:
модель списывает примеры из промпта. Для каждой причины «не исполнилось» — своя строка
в отчёте. Живой локальный прогон с настоящими GitHub и докером, но без публикации, ловит
класс дефектов, недоступный юнит-тестам, и стоит секунд.
